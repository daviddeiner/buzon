BUZÓN CUPISSA — CORRECCIÓN DE CLIENTES, ASUNTO Y ENVÍO

1. Sube TODO el contenido de la carpeta buzon a tu repositorio de Buzón (sin modificar cupissa-admin). Asegúrate de incluir app.js, index.html y sw.js.

2. Supabase Dashboard → proyecto de CUPISSA → Edge Functions → cupissa-buzon.
   - Si no existe: Create a new function con nombre cupissa-buzon.
   - Sustituye el contenido de index.ts por supabase/functions/cupissa-buzon/index.ts del ZIP.
   - Despliega (Deploy).
   - IMPORTANTE: la función debe existir en EL MISMO proyecto que usa Buzón.

3. En Supabase → Edge Functions → Secrets verifica:
   CUPISSA_ADMIN_EMAIL = contacto@cupissa.com
   CUPISSA_MAILER_URL = URL HTTPS del servicio mailer usado por cupissa-emails
   CUPISSA_MAILER_SECRET = el mismo secreto de cupissa-emails
   SUPABASE_URL y SUPABASE_SERVICE_ROLE_KEY: valores del proyecto, configurados en el entorno de Edge Functions.
   No escribas secretos dentro del HTML o JS público.

4. Si la función está protegida por Verify JWT, utiliza una sesión vigente del administrador.
   Se recomienda habilitar Verify JWT para la función. Además, el código verifica que el usuario Supabase Auth sea contacto@cupissa.com.

5. Abre https://buzon.cupissa.com y actualiza con Ctrl+F5; cierra y reabre la PWA si estaba instalada. Inicia sesión.
   Haz clic en «Cargar clientes de Supabase»: consulta clientes_web y clientes, mostrando los nombres y correos válidos y sin duplicados.
   El asunto inicia vacío y solo se rellena si tú escribes en él.

6. Antes del envío comercial, confirma que los destinatarios autorizaron comunicaciones comerciales.
   Para probar, escribe un asunto, el contenido y usa «Enviarme prueba».
   Si aparece Failed to fetch, el navegador no pudo obtener respuesta HTTP de la función: revisa despliegue, URL del proyecto, CORS, consola/red del navegador y extensiones que bloqueen peticiones. No significa que el proveedor haya rechazado el correo.
   Si la función responde con HTTP y un error del mailer, revisa sus Secrets y los logs de Edge Functions.

NOTA: En este entorno no se pudo realizar un envío real ni comprobar tu despliegue de producción. No se modifica cupissa-admin.

PROGRAMACIÓN DE MENSAJES (v7) — configuración obligatoria una sola vez
1. Ejecuta supabase/sql/01_programacion.sql en SQL Editor de Supabase.
2. En Edge Functions → Secrets añade CUPISSA_BUZON_CRON_SECRET con una cadena aleatoria privada de al menos 32 caracteres. Conserva los secretos existentes.
3. Actualiza y despliega cupissa-buzon con el index.ts incluido. Conserva la verificación JWT existente (el cron utiliza la clave anon JWT pública del proyecto y además exige el secreto privado).
4. Abre supabase/sql/02_activar_cron.sql, copia al SQL Editor y reemplaza CAMBIA_ESTE_SECRETO por el mismo secreto del paso 2 (solo dentro de SQL Editor; nunca lo publiques). Ejecuta el SQL.
5. Publica la web actualizada, sin subir secretos ni modificar otras aplicaciones. Actualiza con Ctrl+F5.
6. Prueba seleccionando únicamente tu propio correo, confirma el consentimiento y programa un mensaje para unos minutos después. Cierra la web. Consulta luego Ver programados.
La hora es Colombia (UTC-05:00). El cron revisa cada minuto y procesa hasta 10 correos por ejecución, en paralelo; campañas mayores continúan en minutos sucesivos. La recepción exacta depende del proveedor y no se garantiza al segundo. Los errores quedan registrados y no se reintentan automáticamente para evitar duplicados cuando no se conoce el resultado. Cancelar pendientes no cancela correos ya en proceso. La programación solo funciona tras configurar SQL, secreto y Edge Function. No se ha probado contra Supabase ni enviado correos reales.
